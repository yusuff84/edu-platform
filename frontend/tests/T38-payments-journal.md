## Поиск, период, ключ запроса

- **Поиск** (`admin.searchStudent`, кнопка — `catalog.searchButton` «Найти»,
  переиспользование существующего ключа) правится локально в состоянии
  `searchInput` и попадает в URL (`?q=`) **по Enter или по кнопке**, не на
  каждый символ. URL — источник истины: `useEffect` подтягивает `?q=` обратно
  в поле (сброс фильтров, переходы по истории, ссылки). Применение сбрасывает
  `page`.
- **Период**: два поля `type="date"` (`admin.periodFrom`/`admin.periodTo`)
  в группе `admin.period` (`role="group"` + `aria-label`); изменения сразу
  пишутся в URL (`?from=`/`?to=`, пустая строка удаляет параметр) и сбрасывают
  `page`. Границы включительные — это семантика бэкенда T31, клиент строки дат
  не преобразует (формат `ГГГГ-ММ-ДД` из `<input type="date">`).
- **Валидация**: `from > to` (сравнение строк — для формата `ГГГГ-ММ-ДД`
  лексикографический порядок совпадает с хронологическим) → показывается
  `admin.periodInvalid` (`role="alert"`), запрос **не уходит**:
  `useQuery` получает `enabled: !periodInvalid`. Кнопка выгрузки в этом
  состоянии заблокирована. Мусорные даты, попавшие в URL вручную, клиент не
  фильтрует — их отклонит бэкенд `400`, как и описано в контракте.
- **Ключ запроса**: `['admin-payments', { page, limit, status, courseId, q, from, to }]`
  — ровно как в ТЗ; пустые значения в ключе — `''` (как было для `status`/`courseId`).
- **Сброс фильтров** (`admin.resetFilters`) по-прежнему делает
  `setSearchParams({})` — новые параметры живут в URL, поэтому сбрасываются
  вместе со старыми, поле поиска очищается через синхронизацию с URL.
- Модерация, комиссия, пагинация, `reviewQueue` не тронуты.

## Выгрузка CSV

Кнопка `admin.exportCsv` (в панели фильтров, `title` = `admin.exportCsvHint`)
загружает **всю выборку по текущим фильтрам**, а не открытую страницу:

- постранично `limit=100` до `total`; предохранитель — **не больше 50 страниц**,
  т. е. максимум **5000 строк** (константа `EXPORT_MAX_PAGES`); если выборка
  больше, файл обрезается по 50-й странице, без предупреждения в UI —
  ограничение зафиксировано здесь и в комментарии кода;
- пустая выборка → `admin.exportEmpty`, файл не создаётся;
- успех → `admin.exported` тем же механизмом, что `admin.commissionSaved`
  (`<p role="status">`); ошибка сети/API → текст ошибки `<p role="alert" class="error">`
  (`errorText`, как в существующих блоках);
- CSV: разделитель `;`, BOM `\uFEFF` (Excel), каждая ячейка в кавычках,
  внутренние кавычки удваиваются, строки — CRLF; имя
  `payments-<ГГГГ-ММ-ДД>.csv` (локальная дата); скачивание через
  `Blob` + `URL.createObjectURL` + временная ссылка, затем `revokeObjectURL`.

### Колонки CSV

Ровно 9 колонок, в порядке таблицы журнала; все заголовки — существующие
ключи словаря:

| Заголовок (ключ) | Значение |
| --- | --- |
| `admin.colDate` («Дата») | `formatDate(createdAt)` |
| `admin.colStudent` («Студент») | `studentName \|\| studentEmail \|\| shortId(studentId)` — как в таблице |
| `admin.colCourse` («Курс») | `courseTitle` |
| `admin.colAmount` («Сумма») | `formatMoney(amountCents)` |
| `admin.colCommission` («Комиссия») | `formatMoney(platformFeeCents)` |
| `admin.colTeacher` («Преподавателю») | `formatMoney(teacherAmountCents)` |
| `admin.colProvider` («Провайдер») | `provider` |
| `admin.colStatus` («Статус») | русская подпись через `STATUS_LABEL` |
| `admin.colPaymentId` («ID платежа») | `providerPaymentId` |

**Расхождение в ТЗ, зафиксировано честно**: в п.3 ТЗ у колонки
`admin.colTeacher` стоит пометка «(email преподавателя)». В ответе
`GET /admin/payments` (контракт US6 + T31 «форма ответа прежняя», тип
`PaymentJournalItem` в `api/types.ts`) email преподавателя отсутствует, поэтому
колонка заполнена суммой преподавателя — так же, как одноимённая колонка
таблицы на странице. Если координатор ожидал иное поле — нужно расширение
контракта T31 и типа, задача этого не позволяет.

Отдельной колонки `Email` (студента) в списке колонок ТЗ нет; email студента
попадает в CSV через ту же fallback-цепочку, что в таблице (имя → email → id).
Заголовки CSV пишутся ключами словаря, «русские литералы заголовков»
(разрешённые ТЗ для ключей, которых нет) не потребовались:
`admin.colCourse` = «Курс» уже существует.

6. **Визуальная раскладка** новой панели фильтров (формы поиска, группы
   «Период») и мобильный вид не проверялись — только сборка.
7. **Гонка «изменил фильтры во время выгрузки»**: выгрузка читает `q/from/to/
   status/courseId` из состояния на момент старта; кнопка на время выгрузки
   заблокирована, но смена URL в другой вкладке/истории может рассинхронизировать
   выборку и сообщение об успехе. Вживую не проверялось.

## 1. Сводка: быстрые переходы (`AdminStats.tsx`)

- Блок стоит сразу под `.ac-head` (заголовок + «Обновить») и рендерится
  всегда — до/вместо загрузки и при ошибке `GET /admin/stats`: переходам
  данные сводки не нужны. Скелетон загрузки и пять карточек цифр — как были.
- Заголовок блока: `t('p7.stats.quickLinks')`.
- Сетка ссылок-карточек: `<nav className="ac-grid ac-links__grid">`, каждая
  ссылка — `className="ac-card ac-link"` — т.е. переиспользованы существующие
  классы карточек AdminStats (`.ac-grid`, `.ac-card`), добавлены только свои
  `.ac-links*`/`.ac-link*` в adminConsole.css (в зоне `.ac-`).
- Язык ключей и переходы (все — `<Link>` из react-router-dom):

| Ключ | Переход | Куда именно |
| --- | --- | --- |
| `p7.stats.linksUsers` «Пользователи» | `/admin/users` | страница T26 |
| `p7.stats.linksCourses` «Курсы» | `/admin/courses` | страница T29/T50 |
| `p7.stats.linksEnrollments` «Записи на курсы» | `/admin/enrollments` | страница T49 |
| `p7.stats.linksJournal` «Журнал платежей» | `/admin#journal` | секция Admin.tsx с якорем |
| `p7.stats.linksQueue` «Очередь модерации» | `/admin#queue` | секция Admin.tsx с якорем |

- Якоря: Admin.tsx рисует `<section id="queue">` и `<section id="journal">`
  (и сам навигирует по ним через `<a href="#…">`), поэтому в пределах
  поставленной задачи хэш-ссылки применены. Свой ScrollToTop маршрутизатора
  поднимает страницу наверх при смене pathname (он не смотрит на hash), так
  что после SPA-перехода `/admin/stats → /admin#queue` браузер показывает
  страницу сверху; якорь срабатывает при прямом открытии/перезагрузке URL
  (`/admin#queue`) — html { scroll-behavior: smooth } из styles.css даёт
  плавную прокрутку. Автоскролл к якорю прямо после SPA-перехода требует
  правки `Admin.tsx` (владелец другой задачи) или `router.tsx` — файлы
  вне разрешённого списка, поэтому оставлено как есть и записано в
  «Ограничения» ниже.
- Стрелка «→» в карточке — декоративная (`aria-hidden="true"`); у nav и
  секции есть aria-label/aria-labelledby из того же ключа.
- A11y-мелочь: при hover/focus-visible карточка краснеет фоном как
  `.ac-chip:hover` (#f3f1ec) и стрелка становится контрастной. На узком
  экране (<720px) `white-space: normal` — «Записи на курсы»/«Очередь
  модерации» переносятся, не обрезаются.

## 2. Записи: экспорт CSV (`AdminEnrollments.tsx`)

- В ряду фильтров (после кнопки «Сбросить фильтры») поставлена группа
  подпись + кнопка: подпись — `t('p7.enroll.exportCsv')` («Экспорт CSV»),
  под ней — без изменений `CsvExportButton` (T40):
  `filename="enrollments-ГГГГ-ММ-ДД.csv"`, `headers={exportHeaders}`,
  `loadRows={() => loadExportRows()}`. Компонент не модифицировался:
  ярлык кнопки остаётся `admin.exportCsv` («Выгрузить CSV»), сообщения
  под кнопкой — его собственные (`admin.exported/exportEmpty/exportTruncated`/
  текст ошибки). Расширять компонент не потребовалось.
- `loadExportRows` — постраничная выгрузка **по применённым фильтрам**
  (`q` после debounce, `courseId`, `status`) тем же `listAdminEnrollments`,
  что и список: `limit=100`, до `total`, потолок 50 страниц = 5000 строк
  (константы один-в-один с AdminUsers/AdminCourses T40 и журналом Admin.tsx
  T43; сообщение `admin.exportTruncated` — «первые 5000 строк» — честно для
  этого потолка). Останавливается на неполной странице и при
  `rows.length >= total`.
- Усечение — `exportTruncated(total, rows.length)` (экспорт из компонента
  T40): если `total` больше выгруженного, компонент показывает свой warn.
- Колонки (8) — как в ТЗ координатора:

| # | Заголовок | Значение |
| --- | --- | --- |
| 1 | `ID` | `row.id` |
| 2 | `adminUsers.colEmail` «Email» | `row.studentEmail` |
| 3 | `adminUsers.colName` «Имя» | `row.studentName` (пустое имя → пустое поле) |
| 4 | `adminEnrollments.colCourse` «Курс» | `row.courseTitle` |
| 5 | `ID курса` | `row.courseId` |
| 6 | `adminEnrollments.colStatus` «Статус» | словарная подпись из `STATUS_LABEL` («Активна»/«Возврат»/«Отозвана») — как в выгрузках пользователей/курсов T40 |
| 7 | `adminEnrollments.colProgress` «Прогресс» | `completed/total (percent%)`, percent через существующий `clampPercent` |
| 8 | `Создан` | `row.createdAt` как есть — ISO от бэкенда (не `formatDate`), чтобы сортировать в Excel |

  Заголовки «ID», «ID курса», «Создан» — короткие подписи прямо в CSV
  (это данные, а не интерфейс) — прецедент: «Slug»/«Создан» в
  `AdminCourses.tsx` из отчёта T40.
- Экранный тост успеха: `t('p7.enroll.exportDone')` («Файл скачан») в
  существующем тосте страницы `.ae-notice` (`role="status"`), ставится, когда
  `loadRows` вернул хотя бы одну строку (= файл будет создан и скачан).
  При пустой выборке и при ошибке тост страницы гасится (`admin.exportEmpty`
  и текст ошибки рисует сам компонент под кнопкой) — пользователь не видит
  двух противоречащих сообщений. Про дубль сообщения при полном успехе —
  в отступлении 1.
- Блокировка кнопки — собственный `busy` компонента T40; `disabled` снаружи
  не передаётся (как в AdminUsers/AdminCourses). Данные для выгрузки
  берутся свежим запросом — с текущим состоянием фильтров, а не из кэша React
  Query.

## Ограничения / отступления (осознанные, записаны в отчёт по правилам задачи)

1. **Дубль успеха при выгрузке.** Постановщик просил тост успеха
   `p7.enroll.exportDone`, не меняя CsvExportButton. Компонент рисует своё
   сообщение `admin.exported` под кнопкой, страница — свой тост `.ae-notice`
   «Файл скачан» над списком; при полном успехе видны оба. Расширять
   компонент (onDone/ярлык-проп) нельзя по условию T40 (props API
   `filename/headers/loadRows/disabled` — как есть), поэтому оба сообщения
   сохранены; при пустой выборке/ошибке тост страницы гасится.
2. **Ярлык кнопки.** Видимый текст кнопки задаёт сам CsvExportButton ключом
   `admin.exportCsv` («Выгрузить CSV») и не переопределяется пропсами;
   замороженный `p7.enroll.exportCsv` («Экспорт CSV») использован как
   видимая подпись группы выгрузки в ряду фильтров, рядом с кнопкой.
3. **Потолок выгрузки 5000, а не «до 1000».** Текст задачи упоминал «до 1000
   строк, как в T43», но и T40 (AdminUsers/AdminCourses), и T43/Admin.tsx
   используют порог 50×100=5000, и замороженный `admin.exportTruncated`
   говорит «первые 5000 строк». Чтобы предупреждение компонента не лгало,
   принят потолок 5000 строк, одинаковый со всеми выгрузками админки.
4. **Хэш-переходы из сводки.** Ссылки на `/admin#journal` и `/admin#queue`
   дают корректный deep-link (при прямом открытии/перезагрузке страница
   отскроллит к секции — у Admin.tsx есть `id="journal"/"queue"`), но сразу
   после SPA-перехода из сводки ScrollToTop маршрутизатора поднимает документ
   наверх (он смотрит только на pathname, не на hash). Автоскролл к якорю
   сразу после SPA-навигации потребовал бы правки Admin.tsx/router.tsx —
   файл не из разрешённого списка, поэтому поведения оставлено как есть,
   фоллоу-ап — владельцу Admin.tsx/router.tsx (скролл по `location.hash`).
5. **Статус в CSV** экспортируется словарной подписью («Активна» и т.п.),
   а не кодом `active` — по прецеденту T40 (в выгрузках пользователей
   роль/статус тоже подписи). Если нужен машинный код, достаточно заменить
   один элемент массива в `loadExportRows`.
6. Браузер/визуальная приёмка: живой стенд и dev-сервер не поднимались
   (порты стенда координатора заняты), как и у большинства агентов волны —
   проверено tsc/vite-сборкой/тестами; визуальную приёмку делает координатор.

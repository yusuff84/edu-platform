# T64 — фронтенд промокодов (конструктор и чекаут)

Ветка: `task/T64-promo-codes-ui`, worktree `wt/t64`.
Контракт: раздел «Эндпоинты волны P8 (T63–T70)» в `Task/00-api-contract.md`
(не менялся). Словарь `ru.json` не менялся — использованы готовые ключи
`p8.promo.*` / `p8.checkout.*` и существующие общие ключи.

## Что сделано

### Типы (`frontend/src/api/types.ts`)

Добавлены аддитивно, без изменения существующих типов:

- `PromoCode` — `id, courseId, code, discountPct, maxUses, usedCount,
  expiresAt: string|null, active, createdAt`;
- `PromoValidation` — `code, discountPct, priceCents, finalPriceCents`.

Типы реэкспортированы из `api/client.ts` (страницы импортируют типы оттуда же).

### API-клиент (`frontend/src/api/client.ts`)

- `createPromoCode(courseId, payload)` — `POST /teacher/courses/{id}/promo-codes`,
  конверт `{promoCode}` распаковывается в `PromoCode`. В тело попадают только
  `code`, `discountPct` и переданные `maxUses` / непустой `expiresAt`
  (`null`/`undefined` не отправляются — `DisallowUnknownFields`).
- `listPromoCodes(courseId)` — `GET` того же пути, конверт `{items}` → массив.
- `deactivatePromoCode(courseId, promoId)` — `DELETE`, `204` → `undefined`.
- `validatePromoCode(courseId, code)` — `POST /courses/{id}/promo/validate`,
  тело строго `{code}`, ответ `PromoValidation`.
- `enroll(courseId, provider = 'mock', promoCode?)` — третий параметр
  необязательный, обратная совместимость сохранена: без кода тело прежнее
  `{courseId, provider}`; пустой/пробельный код не отправляется; переданный
  код обрезается по краям.

Ошибки во всех функциях идут через общий `apiFetch` → `ApiError(status, message)`,
поэтому UI показывает текст сервера как есть.

### Конструктор (`frontend/src/pages/Constructor.tsx`)

Секция «Промокоды» показывается у существующего курса и скрыта в архиве
(контракт: создание/деактивация в архиве → `409`, список там не нужен).

- Форма: код, скидка % (целое 1–90), лимит использований (0 — без лимита),
  «Действует до» (`<input type="date">`, пусто — бессрочно). Дата уходит как
  `YYYY-MM-DDT23:59:59Z`.
- Клиентская предвалидация по замороженным ключам: `p8.promo.codeInvalid`
  (trim+upper, `^[A-Z0-9_-]{3,32}$`), `p8.promo.discountInvalid`,
  `p8.promo.maxUsesInvalid`, `p8.promo.expiresInvalid` (дата должна быть
  в будущем). Ошибки выводятся под полями, фокус — на первом неверном поле.
- Список (`GET` под ключом `['promo-codes', courseId]`): код, скидка,
  «Использовано: N / лимит» либо «Использовано: N · Без лимита», срок
  (`formatDate`, для `null` — «—») и статус, вычисляемый на клиенте:
  `inactive` (active=false) важнее `expired` (active=true, `expiresAt` в прошлом),
  иначе `active`.
- «Отключить» — inline-подтверждение в строке (`p8.promo.turnOffConfirm`,
  «Подтвердить/Отмена»), без `window.confirm`, в стиле T49/T52/T57.
- После создания/отключения — `invalidateQueries(['promo-codes', courseId])`,
  уведомления `p8.promo.created` / `p8.promo.turnedOff`.
- Ошибки сервера (дубликат, архив, 403/404) — текстом `ApiError.message`
  в общем уведомлении страницы.

### Страница курса (`frontend/src/pages/Course.tsx`)

Промо-блок показывается только для платного курса вошедшему пользователю без
активной записи (`showPromo`); бесплатный курс работает как раньше.

- Тоггл `p8.checkout.promoToggle` → поле `p8.checkout.promoLabel` + кнопка
  `p8.checkout.apply` (Enter отправляет форму). Проверка — `validatePromoCode`.
- Успех: полная цена зачёркнута (`<s>`), рядом итоговая; кнопка покупки —
  `p8.checkout.buyFor <итог>` (`formatMoney(finalPriceCents)`); блок
  `p8.checkout.applied` + кнопка `p8.checkout.remove` для снятия кода.
- Покупка вызывает `enroll(courseId, 'mock', promoValidation.code)`. Ошибки
  (включая тексты промокода: истёк, лимит исчерпан, бесплатный курс) выводятся
  текстом сервера; `409` по-прежнему трактуется как «уже куплено».
- При переходе на другой курс (меняется `slug`, компонент тот же) состояние
  промокода сбрасывается.

## Отклонения от постановки

1. **Распаковка конвертов в клиенте.** `createPromoCode` возвращает `PromoCode`
   (из `{promoCode}`), `listPromoCodes` — `PromoCode[]` (из `{items}`), как это
   уже делают `getCourse`/`myTeaching`/`myCourses`. Внешний контракт API при
   этом не меняется.
2. **Роль в чекауте не ограничена `student`.** Промо-блок показывается любому
   вошедшему пользователю без записи на платном курсе — ровно как существующая
   кнопка покупки (роль не проверялась и раньше); контракт `validate` разрешает
   любой вошедший аккаунт. Скрывать блок от teacher/admin не требуется
   постановкой и сломало бы единообразие.
3. **Статус «Истёк» считается только для активных кодов.** Если код отключён
   и срок истёк, показывается «Отключён» (действие пользователя важнее срока);
   для активного кода с прошедшим `expiresAt` — «Истёк». Отдельного поля статуса
   в контракте нет, поэтому правило целиком клиентское.
4. **`Content-Type` у `DELETE`.** Общий `apiFetch` всегда ставит
   `Content-Type: application/json`, даже когда тела нет. Это существующее
   поведение транспорта (как у прочих DELETE в клиенте), тела запрос не имеет;
   backend его не читает. Тест это фиксирует явно.

## Открытые вопросы

1. **Бэкенд T63 ещё не в этой ветке.** UI и тесты построены строго по
   замороженному контракту; сквозную проверку с реальным API нужно сделать
   после слияния T63 (особенно коды ошибок промокода и аддитивные поля платежа
   `promoCode`/`discountCents`, которые фронт не отображает — журнал платежей
   вне рамок T64).
2. **Дата «действует до» и часовые пояса.** По постановке выбранная дата
   отправляется как конец дня UTC (`YYYY-MM-DDT23:59:59Z`). Для пользователя
   в отрицательном UTC-смещении поздним вечером «сегодня» уже может быть
   в прошлом, и клиентская предвалидация справедливо покажет
   `p8.promo.expiresInvalid` (контракт требует срок в будущем). Если нужен
   «конец локального дня» — это изменение постановки, не реализовывал.
3. **Пустой список промокодов и пустой курс.** Секция показывается и в
   черновике, и на опубликованном курсе (кроме архива) — по постановке
   «для существующего курса (не для архива)». Если промокоды должны быть
   доступны только опубликованным курсам, это надо уточнить: сейчас API-контракт
   такого ограничения не задаёт.

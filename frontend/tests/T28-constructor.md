## 2. Структура курса

- В шапке курса — сводка по уже загруженному `CourseDetail`:
  `Структура курса: Модулей: N · Уроков в курсе: M` (ключи `teach.structure`,
  `course.modulesCount`, `teach.lessonsCount`); считается через
  `modules.reduce((n, m) => n + m.lessons.length, 0)`, без дополнительных запросов.
- Селект «Перенести в модуль…» (`teach.moveLesson`) в редакторе урока: виден только
  при `editingLessonId && editable && modules.length > 1` (`editable` ⇔
  `status === 'draft'` — в других статусах backend вернёт 409, кнопку не даём нажать).
  В списке — модули, кроме текущего модуля урока. По выбору → `moveLesson(courseId,
  lessonId, moduleId)` (POST `/teacher/courses/{id}/lessons/{lessonId}/move`,
  тело `{moduleId}`) → инвалидация `['teach-course']`/`['teaching']`, сообщение
  `teach.moveLessonDone`, селект возвращается в заглушку, у формы обновляется `moduleId`.
- Перестановка кнопками `teach.moveUp`/`teach.moveDown`: вопросы квиза, варианты ответа,
  тесты код-задачи (см. п. 5).

## 5. Где пересчитывается `correct` и почему это верно

Индекс правильного ответа — это позиция строки внутри `question.options`, поэтому при
любой перестановке **содержимого** вариантов его нужно двигать вслед за вариантом.

1. **`moveQuestion(qi, dir)`** — перестановка вопросов квиза. Меняются местами целиком
   объекты `QuestionState`, а `correct` хранится внутри вопроса и «едет» вместе со
   своими `options`. Пересчёт не нужен по построению — ключ не может отвязаться.
2. **`moveOption(qi, oi, dir)`** — перестановка вариантов внутри вопроса. Меняются
   местами `options[oi]` и `options[j]`, `j = oi + dir`, затем ключ пересчитывается
   точечно:
   - `correct === oi` → `correct = j` (правильный вариант уехал на позицию `j`);
   - `correct === j` → `correct = oi` (правильный был у соседа и уехал на `oi`);
   - иначе — не меняется (ни содержимое позиции `correct`, ни сама позиция не затронуты).
   Это биекция `f: f(oi)=j, f(j)=oi, f(x)=x` — инвариант «`options[correct]` — тот же
   текст, что и до перестановки». Проверено исчерпывающей симуляцией на Node:
   `n = 2..6` вариантов × все `correct` × все позиции × оба направления — 180 кейсов,
   0 нарушений инварианта.
3. Дополнительно уже существовавшие места: `removeOption` обрезает `correct` в диапазон
   нового массива (`Math.max(0, Math.min(...))`), радио «Правильный вариант» задаёт
   `correct = oi` явно.
4. **`moveTest(ti, dir)`** — тесты код-задачи: у теста нет ссылочного индекса, порядок
   тестов и есть порядок проверки, поэтому достаточно обмена соседних элементов.

Границы защищены: `j` вне массива → no-op, кнопки на краях `disabled`.

## 6. Литералы без ключей в `ru.json`

- `«Заполните текст, чтобы увидеть предпросмотр»` — пустой черновик
  (`components/LessonPreview.tsx`, константа `MSG_PREVIEW_EMPTY`). Кандидат в словарь.
- `«Верный ответ»` — бейдж правильного варианта в предпросмотре (`MSG_CORRECT`).
  ТЗ требует именно эту формулировку, ключа с ней в словаре нет. Кандидат в словарь.
- Плейсхолдер `«—»` для незаполненных текстов внутри предпросмотра (вопрос/вариант/тест) —
  данные, а не текст интерфейса; нужен, чтобы позиции вариантов и `correct` были видны.
- В `Constructor.tsx` новых литералов нет: все подписи — существующие ключи
  (`teach.duplicate/archive/unarchive/withdraw/preview/moveLesson/publicPage/structure/
  lessonsCount`, `teach.confirm*`, `teach.*ed`, `course.modulesCount`).
- В `teacherExtra.ts` текстов интерфейса нет.

## 8. Что НЕ проверено / сомнения

- **Сквозной прогон с бэкендом не делался**: T21 пишется параллельно в другом worktree;
  пути/тела/коды взяты из контракта. Все пять вызовов отправляют ровно те поля, что в
  таблице T21, но реальные 201/200/409/400 ответы не наблюдались.
- Ручной проверки в браузере (рендер Markdown в панели, двухколоночный режим, кнопки
  жизненного цикла) не было — только сборка и типы.
- `duplicateCourse`: перед `navigate` идёт `await qc.refetchQueries(['teaching'])`. Если
  этот рефетч не отдаст копию (офлайн/ошибка), после перехода возможен краткий экран
  «курс не найден» до следующей загрузки списка. `refetchQueries` не бросает по умолчанию.
- Селект переноса — с `value=""`: после выбора он всегда возвращается к «—», повторный
  выбор того же модуля недоступен без перешейва страницы (backend-то идемпотентен).
  Выглядит приемлемо, но UX не проверялся вручную.
- «Вернуть из архива» без подтверждения — ключа `teach.confirmUnarchive` в словаре нет.
- Для `review` кнопка «В архив» не показывается, хотя контракт T21 такой переход
  разрешает: следовал матрице ТЗ буквально.
- Маркер `—` в предпросмотре quiz сохраняет видимость индексов вариантов; если это
  сочтут «пустым блоком», легко заменить.

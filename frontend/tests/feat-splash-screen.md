# Splash-экран загрузки

**Ветка:** `feat/splash-screen`  
**База:** `origin/main` (`ab4a905`)

## Что сделано

Добавлен полноэкранный стартовый сплэш: белый фон и по центру
индиго-фиолетовый скруглённый квадрат с белой буквой «S» (по референсу).
Сплэш показывается при холодной загрузке/перезагрузке страницы и плавно
исчезает, когда React отрисовал приложение.

- `frontend/index.html` — разметка сплэша и критичные стили прямо в
  `<head>`, чтобы экран появлялся до загрузки JS-бандла и не мигал
  неоформленным. После скрытия `main.tsx` удаляет узел из DOM.
- `frontend/src/main.tsx` — снятие оверлея: минимум `900ms` от начала
  навигации (для `prefers-reduced-motion` — `350ms`), затем fade-out
  `480ms`. Момент отсчитывается от `performance.now()`, поэтому время
  загрузки бандла учитывается и сплэш не задерживает уже готовое
  приложение.
- Анимация: вход с масштабом/подъёмом (`splash-rise`), мягкое «дыхание»
  логотипа (`splash-float`), пульсация ореола (`splash-halo`) и
  периодический блик по квадрату (`splash-shine`).

## Доступность

- Оверлей: `role="status"`, `aria-live="polite"`, `aria-label="Загрузка"`;
  декоративные элементы скрыты от скринридеров (`aria-hidden="true"`).
- При `prefers-reduced-motion: reduce` все анимации отключаются, остаётся
  статичный логотип; fade-out тоже без анимации.
- `noscript` скрывает сплэш, если JavaScript отключён.
- Контраст: белая буква на градиенте `#7c6bff → #4338ca` — не ниже
  требований AA для крупного текста (буква 58px / 800).

## Проверка

Из `frontend/`:

```text
npm ci
npm run build
```

- `tsc --noEmit` и `vite build` — успешно.
- API-контрактные тесты: `264/264` (после `npm run test:build`;
  запуск списком файлов, т.к. quoted-glob в `npm test` не раскрывается
  в Node 20 на Windows).
- Проверено в Chrome (Puppeteer, production-сборка `vite preview`):
  - на `DOMContentLoaded` сплэш присутствует и непрозрачен;
  - примерно через `900ms` от начала навигации получает класс
    `splash--hidden`, opacity уходит в 0;
  - через `~1.4s` узел `#splash` удалён из DOM;
  - при эмуляции `prefers-reduced-motion: reduce` сплэш статичен и
    скрывается примерно через `350ms + 520ms` без анимации.
- Скриншоты снимались во временный `.tmp` (в коммит не входят):
  старт, reduce-motion и состояние после исчезновения сплэша.

## Ограничения

- Сплэш относится только к старту приложения. Переходы между ленивыми
  маршрутами продолжают использовать существующий `RouteFallback`
  (скелетон внутри оболочки), чтобы не перекрывать интерфейс на каждом
  переходе.
- Стили сплэша намеренно заданы литералами в `index.html`, а не через
  переменные `styles.css`: они должны применяться до загрузки основного
  CSS-бандла.

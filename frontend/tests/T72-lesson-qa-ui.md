## Что сделано

1. **`frontend/src/api/types.ts`** — аддитивно добавлены типы Q&A:
   - `LessonAnswer` (`id`, `questionId`, `authorId`, `authorName`, `authorRole`,
     `isTeacher`, `body`, `createdAt`);
   - `LessonQuestion` (`id`, `courseId`, `lessonId`, `lessonTitle`, `studentId`,
     `studentName`, `body`, `createdAt`, `answers`);
   - `LessonQuestionsPage` (`items`, `total`, `page`, `limit`).

2. **`frontend/src/api/client.ts`** — аддитивно добавлены и реэкспортированы
   функции:
   - `listLessonQuestions(courseId, lessonId?, page?)` — `GET
     /courses/{id}/questions?lessonId=&page=`, конверт с пагинацией как есть;
   - `askQuestion(courseId, lessonId, body)` — `POST /courses/{id}/questions`,
     тело ровно `{lessonId, body}`, конверт `{question}` распакован;
   - `answerQuestion(courseId, questionId, body)` — `POST
     .../questions/{qid}/answers`, тело ровно `{body}`, конверт `{answer}`
     распакован;
   - `deleteQuestion(courseId, questionId)` — `DELETE`, 204 → `void`;
   - `deleteAnswer(courseId, questionId, answerId)` — `DELETE`, 204 → `void`.
   Все id кодируются `encodeURIComponent`; существующие сигнатуры не менялись.

3. **`frontend/src/components/Questions.tsx`** (новый):
   - заголовок «Вопросы и ответы», счётчик, список вопросов текущего урока
     (порядок сервера: новые первыми), ответы старыми первыми;
   - бейдж «Преподаватель» у ответов с `isTeacher`;
   - форма вопроса: textarea `maxLength=2000`, клиентская валидация trim
     10..2000, счётчик символов, «Отправить вопрос»;
   - для гостя — «Войдите, чтобы задать вопрос» со ссылкой на `/login`;
     для вошедшего без записи — «Записывайтесь на курс…»; признак записи
     передаёт `Learn.tsx` из уже загруженного `myCourses()`, при отсутствии
     пропа форма показывается и окончательно решает сервер (403 текстом);
   - форма ответа под каждым вопросом (trim 3..2000), «Ответить» и «Отмена»;
   - удаление своих вопросов/ответов с `window.confirm`; ошибки сервера
     выводятся текстом `ApiError.message`;
   - состояния загрузки, ошибки с «Повторить», пустое состояние;
   - пагинация, если `total > limit` (сервер по умолчанию отдаёт 20);
   - после создания/удаления инвалидируется
     `['lesson-questions', courseId]` — список и счётчик перечитываются.

4. **`frontend/src/pages/Learn.tsx`** — `<Questions>` встроен в `.lesson-pane`

## Отклонения

- Новых ключей i18n не добавлял. Для текстов валидации используются литералы
  контракта: «Вопрос: от 10 до 2000 символов», «Ответ: от 3 до 2000 символов»
  (готовых ключей `p9.qa.*` для них нет).
- Подтверждение удаления ответа — `t('p9.qa.delete') + '?'`: имеющийся
  `p9.qa.deleteConfirm` сформулирован про вопрос вместе с ответами.
- `p9.qa.count` выводится как «N вопросов» без склонения: плюральных ключей
  в замороженном наборе нет.
- `p9.qa.lessonLabel` и `p9.qa.allLessons` не используются: по постановке блок
  всегда показывает вопросы текущего урока, а не все вопросы курса.
- Кнопка «Удалить» показывается только автору сообщения (как в постановке).
  Владелец курса/admin тоже могут удалять по контракту, но их права
  окончательно проверяет сервер; отдельного UI для них не добавлял.
- Для пагинации aria-label «Предыдущая страница» / «Следующая страница» —
  литералы, отдельных ключей нет.
- Успешное удаление ответа не показывает сообщение (ключа нет); список просто
  перечитывается. Удаление вопроса показывает `p9.qa.deleted`.

## Открытые вопросы

- Бэкенд T71 в этом worktree отсутствует; клиент и UI проверены на мок-сервере
  строго по замороженному контракту. Совместимость с реальным ответом нужно
  подтвердить после слияния T71.
- Стоит ли показывать кнопку удаления преподавателю/admin для чужих
  сообщений — сейчас это делает только сервер, UI ориентирован на автора.
- При большом числе вопросов сервер отдаёт по 20 на страницу; клиент
  пагинирует стрелками. Если понадобится «Показать ещё», потребуется
  отдельный ключ i18n.

# T66 — каталог: категории, фильтры, серверная сортировка

## Что сделано

### 1. Типы API (`frontend/src/api/types.ts`)

- `CourseItem.category?: string` — аддитивное поле карточки каталога (T65).
- `CategoryStat { slug, coursesCount }` — элемент ответа `GET /categories`.
- Дополнительно объявлены доменные типы фильтров: `CourseCategory`,
  `CoursePriceFilter` (`free | paid`), `CourseMinRatingFilter` (`3.5 | 4 | 4.5`),
  `CourseSort` (`popular | new | rating | price_asc | price_desc`).

### 2. API-клиент (`frontend/src/api/client.ts`)

- `listCourses` принимает необязательные `category`, `price`, `minRating`, `sort`.
  Параметры уходят в query через существующий `buildQuery`: `undefined` и пустые
  строки не отправляются. Старые вызовы (`q/page/limit`) работают без изменений.
- Добавлена `getCategories(): Promise<CategoryStat[]>` — `GET /categories`,
  конверт `{ items }` распаковывается в массив.
- Новые типы реэкспортированы из `client.ts` (страницы импортируют их оттуда).

### 3. Страница каталога (`frontend/src/pages/Catalog.tsx`)

- Удалены захардкоженные `PILLS` (подменяли `q`) и клиентская сортировка
  (`SEGS` + `useMemo`): сортировка и фильтрация теперь только серверные.
- Панель фильтров:
  - категории — чипы из `getCategories()` + «Все курсы», со счётчиками
    `coursesCount` (если сервер вернул > 0);
  - цена — «Любая / Бесплатные / Платные»;
  - рейтинг — «Любой / 3,5 и выше / 4,0 и выше / 4,5 и выше»;
  - сортировка — селект «Сначала популярные / новые / с высоким рейтингом /
    дешёвые / дорогие»;
  - кнопка «Сбросить фильтры» (неактивна, когда фильтров нет и страница первая).
- На экранах ≤ 960px панель сворачивается: виден тоггл «Фильтры» /
  «Скрыть фильтры» (`aria-expanded`, `aria-controls`), панель раскрывается
  классом `is-open`.
- URL — единственный источник истины: `q, category, price, minRating, sort,
  page` читаются при загрузке и пишутся при изменении. Локально живут только
  черновик строки поиска (до debounce) и флаг свёрнутости панели. Неизвестные
  значения параметров игнорируются (не уходят в запрос).
- Любое изменение фильтра или поиска удаляет `page` (страница 1); поиск
  сохраняет debounce 300 мс; `page=1` в URL не дублируется.
- Фильтры, сортировка и пагинация добавляют запись в history (работают
  «назад/вперёд»); debounce поиска пишет через `replace`, чтобы не засорять
  историю каждым символом.
- «Найдено: N» выводится из `total` серверного ответа.
- Empty state: при активных фильтрах — `p8.catalog.nothingFound` +
  `p8.catalog.nothingFoundHint` + кнопка сброса; для пустого каталога без
  фильтров сохранён прежний экран с CTA для учителя/входа.
- Пагинация переведена на URL (`page`), логика «показано N из M» сохранена.
- Маркетинговые блоки (`DiplomaBlock`, `DreamsBlock`, `FinalCta`, `LeadBlock`,
  `PerksBlock`, `SupportBlock`) и общая вёрстка не менялись.

### 4. Карточка курса (`frontend/src/components/CourseCard.tsx`)

- Если у курса есть `category`, под обложкой показывается бейдж с названием из
  `p8.cat.*` (неизвестный слаг выводится как есть). Бейдж вынесен в тело
  карточки, чтобы не перекрывать существующий тег «Курс» на обложке.

### 5. Стили (`frontend/src/styles/catalog-filters.css`, новый)

- Панель фильтров, чипы, счётчики, селект, кнопка сброса, бейдж категории.
- Только переменные/подходы дизайн-системы (`--line`, `--surface`, `--fg`,
  `--muted`, `--sun-soft`, `--font`), скоуп по `.catalog-page`.
- Адаптив: 4 колонки на десктопе, 2 на ≤ 960px, 1 на ≤ 620px; тоггл панели
  виден только на ≤ 960px. `catalog.css` и `styles.css` не изменялись.

### 6. Тесты (`frontend/tests/api-contract/catalog-filters.test.mjs`, новый)

- Все новые параметры `listCourses` уходят в query (совместно и по одному).
- Пустые/`undefined` параметры не отправляются.
- Конверт `{ items, total, page, limit }` и `category` карточки сохраняются.
- `getCategories`: `GET /categories` без query, распаковка `{ items }` в массив,
  пустой список → `[]`.

## Отклонения от постановки

1. Значения по умолчанию в URL не дублируются: при `sort=popular`, пустых
   фильтрах и `page=1` соответствующие параметры отсутствуют. Отсутствие
   параметра означает дефолт контракта; при смене значения параметр пишется,
   при возврате к дефолту — удаляется. Это сохраняет «единственный источник
   истины» и чистые ссылки.
2. Для пустого каталога **без** активных фильтров оставлен прежний empty state
   (с CTA «создать курс»/«войти»), а не `p8.catalog.nothingFound`: сброс
   фильтров там ничего не изменил бы. Для пустой выдачи по фильтрам/поиску
   используются требуемые ключи и кнопка сброса.
3. Список категорий имеет резерв: если `GET /categories` недоступен или вернул
   пустой массив (T65 идёт параллельно), панель показывает фиксированные шесть
   слагов без счётчиков — фильтрация продолжает работать.
4. Кроме `CategoryStat` в `types.ts` добавлены типы-объединения фильтров
   (`CourseCategory`, `CoursePriceFilter`, `CourseMinRatingFilter`,
   `CourseSort`) для типобезопасности сигнатур; они аддитивны.
5. Бейдж категории размещён в теле карточки, а не поверх обложки: на обложке
   уже есть тег «Курс», и наложение бейджей ломало бы вид плитки.
6. Из hero удалены только хардкод-пилюли `PILLS`; ссылка «Помогите выбрать»
   и общая разметка hero сохранены.

## Открытые вопросы

- Нужно ли всегда писать `sort=popular` в URL явно (сейчас дефолт опускается)?
  Текущее поведение выбрано как более чистое для шаринга ссылок.
- Счётчики категорий появляются только после ответа T65; до этого/при ошибке
  чипы показываются без чисел. Если нужен другой fallback (например, скрывать
  категории с `coursesCount = 0`) — это отдельное UX-решение.
- История: изменения фильтров/сортировки/страницы добавляют записи, debounce
  поиска использует `replace`. Если требуется иная granularity истории
  (например, `replace` для всех изменений) — легко переключить.

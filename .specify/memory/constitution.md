## Core Principles

### I. Понятность новичку (NON-NEGOTIABLE)
Каждый пользовательский сценарий MUST быть проходим новичком без инструкции: каталог, запись на курс, прохождение урока, тест. Любая фича, усложняющая базовый путь ученика, MUST быть упрощена или отклонена. Рациональность: аудитория — новички с нуля, сложность убивает конверсию.

### II. Качество через приглашения и модерацию (NON-NEGOTIABLE)
Публикация курса возможна ТОЛЬКО по схеме: приглашение учителем → черновик в конструкторе → проверка админом → публикация. Прямая самопубликация без проверки ЗАПРЕЩЕНА. Рациональность: доверие новичков держится на проверенном контенте.

### III. API-First и Test-First
Frontend (React) и backend (Go) взаимодействуют ТОЛЬКО через версионированный REST API с OpenAPI-спецификацией. Каждая фича backend MUST иметь контрактные тесты API и unit-тесты ключевой логики до merge. Frontend MUST иметь тесты критических путей (авторизация, оплата, прохождение урока). Red-Green-Refactor обязателен для оплаты, авторизации, прогресса.

### IV. Гибкая оплата по дизайну
Платежи MUST быть изолированы за интерфейсом `PaymentProvider` (создание платежа, webhook, возврат, сверка). Ядро НЕ ДОЛЖНО зависеть от конкретного провайдера. Поддержка нового провайдера (Stripe / Fondy / WayForPay / ЮKassa) — только новый адаптер без изменения доменной логики. Цену задает учитель, комиссию задает платформа в конфиге.

### V. Простота и Docker-First
Стек зафиксирован: React + Go + Docker. Локальный запуск — одна команда `docker compose up`. Новый сервис/зависимость MUST добавлять ценность, иначе YAGNI. MVP-ядро выше расширенных фич (форум, геймификация, встроенное видео).

### VI. Русский язык и доступность
Интерфейс по умолчанию на русском. Все строки через i18n-словарь (подготовка к другим языкам). Auth v1: email + пароль (bcrypt/argon2, сессии/JWT, защита от брутфорса). Вход через Яндекс — как отдельный OAuth-адаптер позже, без переделки ядра auth.

## Технологические ограничения и стандарты
- Frontend: React, маршрутизация, состояние, формы с валидацией.
- Backend: Go, слои handler → service → repository, миграции БД версионированы.
- Инфраструктура: Docker + docker-compose для dev/prod, переменные окружения через `.env`, секреты не в репозитории.
- Данные: пользователи, приглашения учителей, курсы (модули/уроки), записи, прогресс, платежи, отзывы. Персональные данные и пароли хранятся хэшированными.
- Наблюдаемость: структурированные логи Go-сервиса, healthcheck `/healthz`, базовые метрики.
- Производительность v1: каталог открывается < 2с при 100 курсах, поддержка 500 конкурентных читателей.

## Workflow и Quality Gates
- SDD-процесс обязателен: constitution → specify → clarify → plan → tasks → implement → converge.
- Каждая US имеет независимый тест приемки (Given/When/Then).
- Quality gates перед merge: тесты зеленые, OpenAPI обновлен, docker compose пересобирается, конституция соблюдена.
- Code review проверяет соответствие принципам I–VI.

## Governance
Конституция имеет приоритет над всеми остальными практиками. Поправки вносятся через документированное изменение с bump версии: MAJOR — удаление/переопределение принципов, MINOR — новый принцип/раздел, PATCH — уточнения. Каждый PR MUST проверять соответствие конституции. Спорные случаи решает владелец продукта.

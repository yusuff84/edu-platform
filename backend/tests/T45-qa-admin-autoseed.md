## Как работает автосид

`qa-seed-admin.ps1` готовит учётную запись, под которой qa-abc прогоняет админ-блоки
(в P4 её заводили руками: регистрация + PATCH роли):

1. `POST /auth/login` под `-AdminEmail` → 200: готово, exit 0 (идемпотентность: повторный
   запуск ничего не меняет).
2. Иначе вход сид-админом (`-SeedAdminEmail`/`-SeedAdminPassword` — должны совпадать с
   `ADMIN_EMAIL`/`ADMIN_PASSWORD` стенда). 401 → понятная ошибка с подсказкой, exit 1;
   роль сид-учётки проверяется (должна быть `admin`).
3. `GET /admin/users?q=<email>` — поиск учётки (точное сравнение email без учёта регистра).
   Нет — `POST /auth/register` (регистрация всегда создаёт student; прямой выдачи admin нет),
   с повторным поиском на случай гонки (register → 400 «уже существует»).
4. `PATCH /admin/users/{id}/role` `{"role":"admin"}` — идемпотентно (для действующего
   админа тоже 200).
5. Контрольный `POST /auth/login` → 200 и role=admin: exit 0, иначе exit 1.

Все не-GET — с `Origin: http://localhost:3000` (CSRF). На 429 — пауза ~20 с и повтор,
до 4 попыток (как в `qa-p4.ps1`).

В `qa-abc.ps1` провалившаяся первая попытка входа **не идёт в счёт проверок**:
`Invoke-Check` для B1 вызывается один раз по финальной попытке, поэтому число проверок
осталось 49 в обоих режимах. Без автосида (`-NoAutoSeed` или `-SkipAdmin`) поведение прежнее.

## Не проверено / ограничения

- **`-SeedAdminEmail`/`-SeedAdminPassword` должны совпадать с `ADMIN_EMAIL`/`ADMIN_PASSWORD`
  стенда** (или передаваться явно и в `qa-seed-admin.ps1`, и в `qa-abc.ps1`). На стенде с
  нестандартным сид-админом дефолты не подойдут — скрипт упадёт с понятной ошибкой 401.
- **Уже существующая учётка с другим паролем**: сид найдёт её, роль выставит (идемпотентно),
  но контрольный вход упадёт → exit 1. Пароль существующей учётки скрипт не меняет (в API нет
  смены чужого пароля).
- **Регистрация даёт роль student**: admin назначается отдельным PATCH — так и задумано
  контрактом (прямой регистрации админа нет).
- **429 у самого `qa-abc.ps1`**: у B1/первых попыток ретраев нет (как и раньше); если первый
  вход упадёт из-за 429 и автосид включён, сид подождёт лимит и восстановит вход, без автосида
  первый вход при 429 упадёт как раньше. В приёмке этот сценарий не форсировался; повтор на
  429 проверен на `qa-seed-admin.ps1` (см. п.6).
- **PowerShell 7 (`pwsh`)**: на машине не установлен; скрипты проверены только на PS 5.1 —
  они совместимы с обеими версиями по построению (как qa-abc/qa-p4 до них).
- **Прогоны выполнены на живом стенде** (`localhost:8082`), web — на `3001`, поэтому
  `-WebUrl http://localhost:3001` (иначе A0 уходит в SKIP по дефолтному `:3000`).
- Приёмка шла через `.ps1`-вызов в том же процессе PowerShell 5.1 (лог в UTF-8), эквивалентно
  `powershell -File`: `$LASTEXITCODE`/`exit` скриптов проверены (в т.ч. вложенный вызов сида).
- Побочный эффект: на стенде остались созданные прогонами учётки (`qa-admin`, `qa-seed-*`,
  qa-student/qa-teacher с метками) — это нормально для qa-скриптов, повторные прогоны идут 49/49.

# T02 — Словарь и типизированные i18n-ключи

**Ключ сессии:** `T02-i18n-contract`
**Волна:** 1 · **Слой:** frontend
**Приоритет:** P1 — блокирует T03–T06, T08 (они будут использовать эти ключи)

## Проблема

- `frontend/src/i18n/t.ts` экспортирует тип `RuKey`, но он **нигде не используется** —
  вызовы `t('любая строка')` не проверяются компилятором.
- В `ru.json` ~20 неиспользуемых ключей (признаки нереализованных фич).
- Нет ключей под функциональность, которую добавляют T03–T06 и T08.

## Владение файлами (жёсткая граница)

```
frontend/src/i18n/ru.json   — добавить ключи
frontend/src/i18n/t.ts      — типизация
```
Больше ничего. Компоненты, которые их используют, — T03–T06, T08.

## Что сделать

1. Сделать `t()` типобезопасным: тип `RuKey` должен выводиться из `ru.json`
   (через `typeof import('./ru.json')` и рекурсивный ключ-тип) и `t()`
   принимать только `RuKey`. После этого `tsc` отловит опечатки в ключах
   во всех страницах — это бесплатная проверка качества.
2. **Удалить** неиспользуемые ключи (проверь `grep` по `src/` перед удалением):
   `nav.cabinet`, `course.reviews`, `course.modules`, `course.lessons`,
   `auth.errEmailRequired`, `auth.errEmailInvalid`, `auth.errPasswordRequired`,
   `auth.errPasswordShort`, `catalog.free`, `learn.nextLesson`,
   `lesson.video`, `lesson.text`, `reviews.needEnroll`, `teach.myCourses`,
   `common.close`, `common.save`, `common.cancel`, `common.from`, `common.currency`.
3. **Исправить** `auth.success` — он ошибочно используется как текст успешного
   приглашения (`Admin.tsx:28`). Разделить на `admin.inviteCreated` и
   сохранить `auth.success` для реального назначения.
4. **Добавить** ключи, нужные задачам второй волны. Сгруппируй по префиксам,
   все значения — по-русски:

   `learn.*` — заголовок, пустой результат, «следующий урок», «вердикт: зачтено /
   не зачтено», «попытка N», «нет доступа — оформите подписку», «прогресс N%».
   `lesson.*` — вид урока (текст/видео/эфир/квиз/код), «задание», «шаблон кода»,
   «запустить», «проверяем…», «тест пройден», «тест провален», «пояснение»,
   «эфир начнётся», «эфир не назначен», «перейти к следующему уроку».
   `code.*` — «вставьте код», «язык», «сбросить к шаблону».
   `course.*` — «программа курса», «уроков: N», «модулей: N», «перейти к обучению»,
   «средний рейтинг», «отзывов: N», «обложка отсутствует».
   `reviews.*` — «ваш отзыв», «оставить отзыв», «вы уже оставляли отзыв»,
   «нужна активная запись на курс», «нет отзывов», «оценка».
   `teach.*` — «мой курс», «редактировать модуль», «удалить модуль», «вверх», «вниз»,
   «добавить урок», «редактировать урок», «удалить урок», «на модерацию»,
   «курс отклонён модератором», «комментарий модератора», «статус: черновик/на проверке/опубликован/в архиве».
   `admin.*` — «журнал платежей», «комиссия платформы, %», «сохранить»,
   «всего», «комиссия», «преподавателю», «платёж отклонён», «загрузка…», «платежей нет».
   `error.*` — «страница не найдена», «что-то пошло не так», «вернуться в каталог»,
   «повторить попытку», «нет доступа», «слишком много запросов».
   `common.*` — переиспользовать существующие; добавить «сохранить», «отмена»,
   «удалить», «закрыть», «готово».

5. Проверь, что все новые ключи **покрывают** потребности T03–T06, T08,
   перечисленные выше. Лучше добавить с запасом, чем конфликтовать во второй волне.

## Критерии приёмки

- [ ] `t()` принимает только валидные ключи; `npx tsc --noEmit` в `frontend/` проходит
- [ ] Неиспользуемые ключи удалены, новые покрывают нужды T03–T06, T08
- [ ] Все значения на русском языке, без английских заглушек
- [ ] `RuKey` реально используется в сигнатуре `t()`

## Проверка

```bash
cd frontend
npx tsc --noEmit
```

> ⚠️ После того как T01–T11 попадут в интеграционную ветку, `tsc` может
> начать ругаться на отсутствующие ключи в ещё не смерженных страницах —
> это ожидаемо и лечится в волне 2. Убедись, что ругается **только** на это.

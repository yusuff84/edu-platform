## 1. Ссылка `/register?inviteToken=...` никуда не ведёт (P0)

**Симптом:** админ создаёт приглашение и копирует ссылку. Преподаватель по ней
переходит — а `Auth.tsx` читает `inviteToken` **только из state формы**, не из
query-параметров. Ссылка открывает обычную регистрацию **без роли teacher**:
пользователь создаётся студентом, приглашение не потребляется.

Фактически **весь флоу приглашений (US3) не работает** — T08 красиво отдаёт
токен в админке, а принять его нечем.

**Что сделать:**
1. В `Register` брать `inviteToken` из `useSearchParams()` (query), а не только
   из формы.
2. Подставить его в тело `register()` — `client.ts` уже передаёт `inviteToken`
   опционально (T01).
3. Показать пользователю понятное состояние: что он приглашён, на какую почту
   (если бэкенд это отдаёт — проверь), и что регистрация даст роль
   преподавателя.
4. Если токен **просрочен/недействителен** — бэкенд ответит ошибкой.
   Покажи понятный русский текст, а не сырой envelope.
5. **Не сломай** регистрацию без токена (обычный студент) и поле формы
   `inviteToken`, если оно есть.

**Ключ словаря:** `ru.json` не правь. Если ключа не хватает — используй
существующий по смыслу и **перечисли нехватку в отчёте**.

## 2. Уже авторизованный не редиректится со страницы входа (P1)

**Симптом:** вошедший пользователь открывает `/login` — получает форму входа.
Логично перенаправить его дальше (`/me` или на `state.from`, если он есть —
но `from` ставится только гвардами, т.е. только для **неавторизованных**).

**Что сделать:** если `me()` уже возвращает пользователя — `<Navigate to="/me" replace />`
(или на `location.state.from`, если он есть и безопасен). Используй **тот же
query-ключ `['me']`**, что и `RouteGuards.tsx`/`Layout` — TanStack Query
дедуплицирует, **не создавай второй запрос**.

То же для `Register`.

**Осторожно:** `RequireAuth` ведёт неавторизованного на `/login` c
`state.from`. Если `from` задан — редирект после входа уже обрабатывает T15
(функция `resolveRedirectFrom`). Не дублируй и не перебивай её логику.

## 3. `formatPrice(0)` возвращает «Бесплатно» — неверно в итогах (P2)

**Симптом:** `client.ts` → `formatPrice(0)` отдаёт строку `«Бесплатно»`.
Это приемлемо для **цены курса**, но **неприемлемо** для:
- итогов журнала платежей (`totals.amountCents`, `platformFeeCents`, `teacherAmountCents`);
- отображения комиссии;
- любого числового денежного значения, где 0 — это «ноль», а не «бесплатно».

T08 обнаружил это и обошёл **локальным форматтером `money()`** прямо в
`Admin.tsx` — получилось дублирование и два разных формата в одном интерфейсе.

**Что сделать (выбери и обоснуй):**
- **Вариант А (предпочтительный):** разделить семантику —
  `formatPrice(cents)` оставить для цены (с «Бесплатно»), а добавить
  `formatMoney(cents)` без этой подмены, и **вернуть `Admin.tsx` на общий
  форматтер**, удалив локальный `money()`.
- **Вариант Б:** убрать «Бесплатно» из `formatPrice` совсем и явно писать
  `«Бесплатно»` там, где это осмысленно (в `Course.tsx` и т.п.) — но тогда
  придётся править чужие страницы, а `Course.tsx` сейчас не в твоём владении.
  **Если выбрал Б — не правь чужие файлы, перечисли их в отчёте.**

Проверь grep'ом все вызовы `formatPrice` перед изменением:
```
grep -rn "formatPrice\|money(" frontend/src
```

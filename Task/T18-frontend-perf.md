## 1. Route-based code splitting (главное)

`router.tsx` импортирует все страницы статически. Переведи на `React.lazy` +
`Suspense` тяжёлые и редкие маршруты:

| Страница | Почему ленивая |
|---|---|
| `Admin` | видна только админу |
| `Constructor` | видна только преподавателю |
| `Learn`, `LessonView` | открываются после входа |
| `Cabinets`, `MyCourses` | то же |
| `NotFound`, `marketing` | редки |

**Каталог (`Catalog`, `Course`, `CourseCard`) оставь статическим** — это
первый экран анонимного посетителя, он не должен ждать второй загрузки.

**Требования:**
- `Suspense` с осмысленным состоянием загрузки по-русски.
  **`ru.json` не правь** — используй существующий ключ (например `learn.loading`,
  `common.*`), нехватку перечисли в отчёте.
- Оберни ленивые маршруты в `ErrorBoundary` — он уже есть (`T05`).
- **Не меняй ни один `path` и ни один guard** (`RequireAuth`, `RequireRole`).
  Итоговая таблица маршрутов обязана совпасть с зафиксированной в T05.

**Было/стало:** зафиксируй размер `dist/assets/index-*.js` до и после.

## 2. CSS: дедупликация после слияния дизайн-системы

`styles.css` вырос на +2275 строк за счёт порта дизайн-системы, и при этом
T03–T08 **добавили свои файлы**: `learn.css`, `catalog.css`, `constructor.css`,
`admin.css`, `shell.css`. Высок риск дублей и конфликтов специфичности.

**Что сделать:**
- найди дублирующиеся правила и объедини:
  `grep -oE '^\s*\.[a-zA-Z][a-zA-Z0-9_-]*' frontend/src/styles.css | sort | uniq -c | sort -rn | head -40`
- убери правила, определённые **дважды** в `styles.css` (поздние перебивают
  ранние — это источник неочевидных багов);
- проверь, не задублированы ли правила из `styles.css` в подключённых `*.css`
  страниц (`grep -rn "\.learn-grid\|\.card\b" frontend/src/styles/*.css`);
- **порядок подключения `.css` не меняй** без явной причины — приоритет зависит
  от порядка.

**Не удаляй** правила, которые используются в `*.tsx`, даже если выглядят
мёртвыми. Проверяй grep'ом по всему `frontend/src`.

## 3. Ререндеры

- `Layout` рендерит `useQuery(['me'])` и всю навигацию — оберни дорогое в
  `React.memo`, стабилизируй обработчики через `useCallback`.
- Проверь, не создаются ли **новые объекты/функции на каждый рендер** в
  `router.tsx` (конфигурация роутов, `errorElement`).
- Ищи очевидное: инлайновые объекты в пропсах тяжёлых списков.

**Измерь:** если возможно, зафиксируй число рендеров или хотя бы аргументацию,
почему изменение безопасно. **Не вводи новых зависимостей** — только React/TS.

## 4. Что НЕ делать

- Не трогай `backend/**` — там T16.
- Не правь `specs/**` (артефакты SDD).
- Не «оптимизируй» вёрстку вслепую: любое правило CSS, которое ты удаляешь,

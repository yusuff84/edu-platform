# T11 — Песочница и лимиты runner

**Ключ сессии:** `T11-runner-sandbox`
**Волна:** 1 · **Слой:** runner (Go)
**Приоритет:** P1 — выполняется произвольный код пользователей

## Проблема

`runner/main.go` выполняет код, присланный студентом, **без изоляции**:

- `runner/Dockerfile:7-10` — `debian:bookworm-slim` + `python3` + `nodejs`,
  `CMD ["runner"]` **от root**, без `USER`;
- комментарий `Dockerfile:8` и `main.go:75-76` обещает «сеть ограничивается
  на уровне контейнера», но в `docker-compose.yml:43-47` у сервиса `runner`
  **нет** ни `network_mode`, ни `mem_limit`, ни `cpus`, ни `read_only`,
  ни `cap_drop` — обещание не выполнено;
- `main.go:78` — таймаут 5 с **на каждый тест**, 10 тестов = 50 с на один запрос;
  при этом `main.go:166` использует `http.ListenAndServe` без `WriteTimeout`,
  поэтому соединение висит бесконечно;
- `main.go:82-85` — `cmd.Stdout` пишется в неограниченный `bytes.Buffer`:
  программа может напечатать гигабайт и съесть память контейнера;
- нет ограничения числа одновременных запусков;
- `runHTML` (`main.go:137-158`) **не исполняет** HTML/CSS, а проверяет
  `strings.Contains` — это не проверка кода, а заглушка;
- `main.go:166` — ошибка `ListenAndServe` игнорируется (`_ =`).

## Владение файлами (жёсткая граница)

```
runner/main.go
runner/Dockerfile
runner/go.mod        — только если нужен пакет без внешних зависимостей
```
`docker-compose.yml` **не трогать** — это зона T13. Опиши нужные параметры
в отчёте, T13 их применит.

## Что сделать

### 1. Лимиты выполнения (`main.go`)

- Один `http.Server` с `ReadHeaderTimeout`, `WriteTimeout` (например 60 с),
  `IdleTimeout`, `MaxHeaderBytes`.
- **Общий бюджет на запрос**: N тестов × 5 с не должны превышать
  `maxRequestBudget` (например 20 с). Реализуй через
  `context.WithTimeout` на весь `runHandler`, а не на каждый `runCmd`.
- `MaxBytesReader` оставь (200 КБ), но добавь ограничение вывода:
  используй буфер с ограничением 256 КБ и обрывай запись при переполнении
  (кастомный `io.Writer`, возвращающий ошибку после лимита).
- Считай CPU/память процесса, если доступно без новых зависимостей —
  хотя бы через `SysProcAttr` и периодический `Process.Signal(syscall.SIGKILL)`
  по таймауту (на Windows-хосте это не сработает, поэтому держи
  `exec.CommandContext` как основной механизм).
- **Семафор** ограничения конкурентности: `maxConcurrent` (например 4)
  одновременных запусков, остальные получают `503` немедленно, а не висят.
- Не игнорируй ошибку `ListenAndServe`: логируй и корректно завершайся.

### 2. Файлы вместо `-c`

`python3 -c` и `node -e` требуют экранирования и упираются в длину аргумента.
Перейди на запись кода в **временный файл** в каталоге `os.MkdirTemp`
с правами `0700`, запуск `python3 <file>` / `node <file>`, удаление в `defer`.
Это же упрощает перенаправление ввода-вывода.

### 3. Окружение и изоляция процесса

- `cmd.Env` = минимальный белый список (`PATH`, `HOME=<tmp>`, `LANG`), а не наследование.
- Рабочий каталог — `tmp`.
- `cmd.Stdin` — только для `input` теста.

### 4. Реальная проверка HTML/CSS

`htmlcss` сейчас — заглушка. Сделай честную проверку без браузера:
нормализуй ввод/ожидание (trim, сворачивание пробелов, нижний регистр для тегов/атрибутов)
и проверяй наличие требуемых конструкций (теги, атрибуты, CSS-правила).
**Честно напиши в комментарии**, что это статический анализатор, а не рендеринг,
и обнови `error_ru`, чтобы студент понимал ограничение.
Если нужен headless-браузер — не добавляй его (нарушит Docker-First принцип),
опиши это в отчёте как осознанное решение.

### 5. Dockerfile

- Многоэтапная сборка; в финальный образ — только рантайм;
- создай **непривилегированного** пользователя, `USER` в финальном образе;
- рабочий каталог `/tmp` с `chmod 1777`;
- `ENTRYPOINT`/`CMD` через exec-форму.

## Критерии приёмки

- [ ] `cd runner && go build ./...` без ошибок
- [ ] `cd runner && go vet ./...` чисто
- [ ] Есть тесты на: общий таймаут запроса, лимит вывода,
      отказ при переполнении семафора, успешный запуск python и js
- [ ] Бесконечный цикл (`while True: pass`) не держит соединение дольше бюджета
- [ ] Программа, печатающая мегабайты, не роняет процесс
- [ ] `main.go` не содержит `_ = http.ListenAndServe`
- [ ] Контейнер runner не работает от root
- [ ] В отчёте перечислены параметры `docker-compose.yml`, которые применит T13

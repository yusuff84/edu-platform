# T15 — Переход после входа: `Auth.tsx` и `state.from`

**Ключ сессии:** `T05-routing-guards` (продолжение той же сессии)
**Волна:** 2 · **Слой:** frontend
**Приоритет:** P1 — блокирует работу T05

## Почему отдельная задача

Агент T05 (роутинг, гварды) нашёл баг, который **ломает его собственную
работу**, и у файла не было хозяина в волне 2.

`frontend/src/pages/Auth.tsx:36-40` и `:94-98` — после `login()`/`register()`
всегда `navigate('/')`.

Но `RequireAuth` из `frontend/src/components/RouteGuards.tsx` редиректит
анонима на `/login` c `state: { from: location }`. `Auth.tsx` это состояние
игнорирует.

Итог: студент переходит по ссылке на `/teach` неавторизованным → гвард ведёт
на `/login` → вводит логин → оказывается на `/` вместо `/teach`. Гвард не
работает — она лишь добавляет лишний клик и **теряет намерение пользователя**.

Реальный пользовательский путь: «мне прислали ссылку на курс, я должен
зайти и сразу попасть на страницу» — сейчас он разваливается.

## Владение файлами (жёсткая граница)

```
frontend/src/pages/Auth.tsx
```
Только этот файл. `RouteGuards.tsx`, `router.tsx`, `client.ts`, `ru.json` — **не трогать**.

## Что сделать

1. В `Login` и `Register` после успешного входа читать
   `useLocation().state?.from`.
2. Редиректить на `from`, если он есть, иначе на `/`.
3. **Защита от open redirect:** `from` — это объект `Location` от
   react-router, а не произвольная строка. Убедись, что редирект идёт
   только на внутренний путь (`pathname`), а не на внешний URL.
   Если `from` подделан — уводить на `/`.
4. Проверить, что `state.from` не теряется при переходе между
   `Login` и `Register` (есть ссылка «зарегистрироваться» и обратно).
   Перенаправляй `from` при смене формы.
5. Проверить поведение после успешной регистрации **по invite-токену**
   (`inviteToken` из query-параметров). Новый пользователь — преподаватель,
   логичный `from` — `/teach`. Решение за тобой, но обоснуй в отчёте.
6. Не ломать текущую обработку `inviteToken` и сообщение об успехе.

## Критерии приёмки

- [ ] `npx tsc --noEmit` не даёт ошибок в `Auth.tsx`
- [ ] Ссылка на `/teach` → логин → после входа пользователь на `/teach`
- [ ] Ссылка на `/courses/python-s-nulya` → логин → пользователь на странице курса
- [ ] Вход без `state.from` ведёт на `/`
- [ ] Подделанный `from` вида `https://evil.example` не выполняется
- [ ] Переход Login ↔ Register сохраняет `from`

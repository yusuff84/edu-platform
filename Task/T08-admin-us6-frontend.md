## Что сделать

### 1. Очередь модерации (починить, не сломать)

2. `reviewQueue()` после T01 — массив. Проверь рендер и пустое состояние.
3. Карточка курса: название, автор, цена, дата, кнопки
   «Одобрить» / «Отклонить».
4. При отклонении — **обязательное** поле комментария
   (без него backend отдаёт `400`), валидация на клиенте.
5. После решения — инвалидация `['review-queue']`.

### 2. Журнал платежей (новый функционал)

Используй `paymentJournal(params)` из T01 (реализация — T07).
Согласуйся с контрактом `Task/00-api-contract.md`, раздел
«Новые эндпоинты US6».

6. Таблица: дата, студент (id/короткий), курс, сумма,
   комиссия платформы, доля преподавателя, провайдер,
   статус (цветовая метка `pending`/`succeeded`/`failed`/`refunded`),
   `providerPaymentId` (моноширинный, с копированием по клику).
7. **Итоги** из `totals`: «всего», «комиссия», «преподавателя» —
   с явной подписью «по выборке фильтра».
8. **Фильтры:** статус, курс (выпадающий список из загруженной страницы
   журнала или из `reviewQueue`/каталога — выбери и обоснуй).
   Фильтры — в URL query-параметрах, чтобы ссылку можно было передать.
9. **Пагинация** по `page`/`limit`/`total`.
10. Состояния: загрузка, «платежей нет», ошибка с повтором,
    `403` при недостаточной роли.

### 3. Настройки комиссии

11. Поле «Комиссия платформы, %» через `getAdminSettings()` /
    `updateAdminSettings(pct)`. Валидация целого `0..90`.
12. Перед сохранением — подтверждение изменения с указанием,
    что это влияет на **все будущие** покупки (существующие платежи не пересчитываются).
13. После сохранения — сообщение об успехе; при `400` — показать причину.

### 4. Приглашения (починить мелочь)

14. `createInvite()` возвращает токен **один раз** — показывай его
    в заметном блоке с кнопкой «скопировать», а не в молчаливом `alert`.

### 5. Структура страницы

15. Раздели страницу на секции с якорной навигацией
    (очередь / журнал / настройки / приглашения).
16. Все строки по-русски через `t()`; ключи из T02, новые не выдумывать.

## Проверка

```bash
cd frontend
npx tsc --noEmit
npm run build
```

Ручная проверка: вход админом → очередь (отклонить с комментарием) →
журнал (покупка сначала должна быть совершена через mock) →
итоги совпадают с суммой строк → комиссия меняется и переживает перезагрузку.

## Известные средние риски (не блокеры MVP)

- [ ] Платёж создаётся у провайдера до локальной записи: при сбое записи в БД
      остаётся внешний платёж без локального следа; нужна реконсиляция.
- [ ] YooKassa refund использует случайный idempotency key на каждый вызов:
      повтор после сетевого таймаута может создать второй возврат.
- [ ] Stripe `GetStatus` с пустым статусом трактуется fail-safe неявно;
      нужно явное покрытие тестом/веткой.
- [x] Невалидный `YOOKASSA_TRUSTED_IPS` больше не отключает проверку молча:
      непустой, но нераспознанный список отклоняет все вебхуки и пишет warning.
- [ ] Rate-limit логина — по IP, а не по аккаунту; за NAT возможен как
      общий блок, так и распределённый перебор.
- [ ] Идемпотентность и rate-limit вебхуков process-local: несколько реплик
      API требуют общего хранилища/Redis.
- [ ] Старые строки `admin@local`/`teacher@local` в уже существующих
      production-БД не удаляются новой политикой seed — нужна явная миграция
      или ручная проверка.

# T60 — Стили: глобальная база и «каркас» (styles.css, shell.css, формы входа)

**Волна:** P7  **Ветка:** `task/T60-styles-global-shell`  **Worktree:** `wt/t60`

## Суть

«Кривые стили» в общесайтовом файле: кнопки/инпуты/карточки выровнены
по-разному в зависимости от страницы, шапка собирается из разношёрстных
блоков, промо-баннер («Первый курс со скидкой 20%») висит над шапкой без
адаптива, футер дышит. Задача — глобальная роль дезинфекции: общий
лингвистический базис кнопок/форм/карточек + каркас (шапка/футер/скин).

Файлы: `frontend/src/styles.css` (≈2165 строк, главный) и
`frontend/src/styles/shell.css` (каркас). **Только эти два файла.**

## Известные места (проверено замерами)

- Шапка: законопаченный блок промо-баннера; строка поиска и «Начать учиться»
  прилипают на узких экранах; email в чике пользователя не вписывается
  (ломается на 1280–1440);
- «Перейти к содержимому» (skip-link) и версия «фокус-стили» — проверить
  видимость и не мешать Tab-навигации;
- Кнопки: смесь `.btn`, `.btn-primary`, `.btn-ghost`, `.btn-sm`,
  `.btn-danger*` — отступы/скругления/высоты должны быть консистентны при
  любом сочетании;
- Формы (`form-grid`): signup/login/конструктор — выравнивание полей,
  подписи, spacing между группами, disabled-состояния;
- Типографика: заголовки H1–H3 в каркасе и на страницах (крупность/отступы),
  чтобы страницы выглядели единообразно без правки контента;
- Токены: собрать цвета/отступы в :root variables (у остальных css-файлов
  свои хардкоды — НЕЛЬЗЯ их менять; новые перемены определяй аккуратно);
- Тёмные состояния hover/focus/active/disabled для всех .btn-variants;
- Верните в норму `loading`/`spinner` базовые классы (используемые
  RouteFallback и страницами).

## Порядок работы

1. Прочти оба файла целиком; составь в ОТСЧЁТЕ реестр классов, которые
   реально используются на страницах (греpp по `className="…"` в src/):
   мёртвые классы НЕ удалять, пометить в отчёте.
2. Аккуратный рефакторинг: фиксируй «якорные» значения (сколько px — добьюсь
   единообразия), добавь место для переменных в :root, применяй локально
   только внутри этих двух файлов.
3. НЕ трогать селекторы, которые потребляют другие css-файлы (catalog.css и
   т.д.). Общие классы (.wrap, .btn*, .card) усовершенствуются только
   совместимым образом (не ломаяAnyone谁的家里 у них переопределения).
4. Адаптив: 360 / 768 / 1024 / 1440 / 1920 — проверь поумилUN head правил
   (media-кврв): промо-баннер Drawable на ≤768 (сжатие), шапка не
   горизонтально-wrapper, кнопки не прыгают.
5. Формы входа/регистрации — сегодня базовые уucene form-grid живёт в
   styles.css: держи поля и текст-ошибки по сетке; helper text смолл
   (8+ символом (пароль) ин line).

## Критерии готовности

- `npm run build` зелёный; `npm test` зелёный;
- в diff только `styles.css`, `shell.css` (+ отчёт);
- в отчёте — таблица «класс → правило → что изменено» и список
  потенциально затронутых страниц для координаторского визуала.
